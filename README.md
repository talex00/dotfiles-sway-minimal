# dotfiles-sway-minimal

Минималистичное окружение на **Sway** (Wayland): светлая тема, нулевые гэпы, тонкие
рамки и никакого лишнего кода в самих конфигах. Раскладывается через GNU Stow.

## Стек

| Роль | Пакет |
| --- | --- |
| Оконный менеджер | sway + autotiling (спиральный split) |
| Терминал | foot |
| Панель | waybar (вертикальная, слева) |
| Лаунчер и dmenu | fuzzel |
| Уведомления | mako |
| Аутентификация (polkit) | polkit-gnome |
| Блокировка, обои, idle | swaylock-effects, swaybg, swayidle |
| Файловый менеджер | Thunar |
| Буфер обмена | wl-clipboard + cliphist |
| Скриншоты | grim + slurp |
| Цветовая температура | gammastep |
| Батарея | batsignal |
| Диктовка | Handy (хоткей держит sway) |
| Мониторы | nwg-displays |
| Tray | nm-applet, blueman-applet |
| Shell | fish + fastfetch |

## Установка

```bash
yay -S sway swaylock-effects swayidle swaybg autotiling waybar foot fuzzel mako \
    polkit-gnome thunar stow fish fastfetch grim slurp gammastep batsignal \
    wl-clipboard cliphist jq playerctl brightnessctl ddcutil network-manager-applet \
    blueman nwg-displays inter-font adwaita-icon-theme

cd ~/dotfiles-sway-minimal
chmod +x sway/.config/sway/scripts/*.sh sway/.config/sway/scripts/*/*.sh
stow sway foot fuzzel mako fish xfce
~/.config/sway/scripts/look.sh ensure   # state-файлы темы: один раз, дальше сами
```

`swaylock-effects` заменяет обычный `swaylock` — менеджер пакетов предложит замену,
это ожидаемо. Пакет `sway` раскладывает сразу `~/.config/sway`, `~/.config/waybar`
и `~/.config/swaylock`.

## Экран блокировки

Обои те же, что на рабочем столе, без блюра и прочих эффектов. По центру тонкое белое
кольцо, внутри — чёрный с большой прозрачностью, чтобы время читалось на любой
картинке. Время крупное, дата под ним мелкая. Ввод символа подсвечивается зелёным,
стирание — красным. При вводе под кольцом появляется бокс с текущей раскладкой.
Цвета кольца и подсветок зависят от выбранной темы (см. «Внешний вид»): `lock.sh`
подмешивает их флагами из `~/.config/swaylock/theme-colors`, а значения из
`swaylock/config` остаются фолбэком темы `ice`.

Путь к обоям в конфиг swaylock не прописать: там нет ни подстановки команд, ни
раскрытия `~`. Поэтому блокировка идёт через `scripts/lock.sh`: он читает тот же
`~/.config/sway/wallpaper`, что и swaybg, и передаёт картинку в `swaylock -i`.

Главное, что нужно знать при правках `sway/.config/swaylock/config`, — все размеры
завязаны на два параметра:

| Что | Чем задаётся | Сейчас |
| --- | --- | --- |
| кольцо | `indicator-radius` | `300` |
| время | `font-size` | `155` |
| дата | `indicator-radius / 6`, своей опции нет | `50` |
| бокс раскладки | `font-size` | `155` |
| `verifying` / `wrong` / `cleared` | `font-size` | скрыты прозрачным цветом |

Отсюда несколько неочевидных следствий:

- **дату нельзя увеличить или уменьшить отдельно** — она растёт только вместе с
  кольцом. Её ширину подгоняют форматом `datestr`, а не размером шрифта:
  `%a, %-d %B` даёт «пн, 24 августа», а `%A` — «понедельник» и строку вдвое шире;
- **время нельзя увеличить, не увеличив кольцо**: строка шириной больше
  ≈ `0.73 × indicator-radius` за кольцо вылезает. Потолок отношения «время / дата»
  отсюда — около `4.4` (сейчас `3.1`);
- бокс раскладки тоже идёт размером `font-size`, но рисуется **под** кольцом и
  только пока вводится пароль, так что его ширина часам не мешает. С `font-size=155`
  он занимает ещё ≈ 200 px по высоте — на 1080 p влезает, на экране ниже может
  обрезаться — тогда верните `hide-keyboard-layout`;
- а вот `verifying` рисуется внутри круга и при таком кегле шире него, поэтому
  `text-ver-color` / `text-wrong-color` / `text-clear-color` стоят прозрачными;
  состояние видно по цвету кольца;
- прозрачность круга — последние две цифры в `inside-color` (`66` ≈ 40%, `99` ≈ 60%).

`font-size` не умножается на масштаб вывода, а радиус — умножается. На дисплее с
`scale` больше 1 пропорции времени и даты поедут, размер придётся подобрать заново.

Шрифт часов — `Inter` (пакет `inter-font`). Если не хочется лишнего шрифта в системе —
поменяйте `font=Inter` на `font=JetBrains Mono`.

## Диктовка (Handy)

Wayland не даёт приложениям перехватывать глобальные хоткеи, поэтому `Ctrl + Space`
держит sway и переключает запись сигналом `SIGUSR2` — так советует сама
документация Handy. Собственная настройка хоткея внутри Handy не участвует
вообще: комбинацию задаёт только конфиг sway. В настройках Handy нужен режим
toggle, а не push-to-talk: сигнал переключает запись, а не держит её.

```
set $handy pkill -USR2 -x handy || Handy.AppImage
bindsym --to-code Ctrl+space exec $handy
```

Сигналу нужен живой процесс, а Handy сам не поднимается — поэтому он есть и в
автозапуске (`exec $handy`), и вторым шагом в самой команде: если процесса нет,
первое нажатие поднимает приложение, следующее уже включает запись.

Про AppImage важно знать, что процессов два:

```bash
$ pgrep -a -i handy
533140 handy
533144 Handy.AppImage
```

`Handy.AppImage` — это оболочка AppImage, она `SIGUSR2` не обрабатывает и от сигнала
просто умрёт. Нужен ровно `handy` — поэтому `-x` (точное имя) и без `-i`:
регистронезависимость здесь только увеличивает шанс попасть в оболочку.

`Ctrl + Space` sway забирает глобально, и приложения его больше не видят. Если
понадобится автодополнение в IDE или emacs — перевешайте диктовку на другую
комбинацию. С переключением раскладки конфликта нет: оно на `Super + Space`.

## Мониторы

В git нет ни выходов, ни привязки воркспейсов: на разных машинах разные мониторы,
а `git pull` затирал бы локальную раскладку. Оба файла лежат только на машине
и перечислены в `.gitignore`.

**Пути важны.** nwg-displays по умолчанию пишет именно туда, без расширения:

| Файл | Что внутри |
| --- | --- |
| `~/.config/sway/outputs` | `output DP-1 { mode ... pos ... }` |
| `~/.config/sway/workspaces` | `workspace 1 output DP-1` |

Подключаются глобами, а не прямыми путями, чтобы на свежей системе отсутствие
фаи́ла не давало ошибку конфига:

```
include ~/.config/sway/output*
include ~/.config/sway/workspace*
```

Если настройки монитора «сбрасываются» после `reload` или перезахода — практически
всегда дело в том, что include не нашёл файл: без `output`-директив sway берёт у
монитора preferred mode, а не 240 Гц. Проверить, что видит sway:

```bash
ls -la ~/.config/sway/                  # есть ли outputs и не битая ли это ссылка
find ~/.config/sway -xtype l            # битые симлинки после stow/pull
swaymsg -t get_outputs                  # имена выходов и текущий режим
```

Записать раскладку заново — просто `nwg-displays` без аргументов, он сам положит файлы
куда надо; потом `swaymsg reload`.

Встроенный `eDP-1` гасится или включается на старте скриптом
`scripts/monitors-fallback.sh` по наличию внешнего `DP-1` — это единственное, что
осталось привязано к именам выходов. Для автоматики при док/отстыковке лучше
поставить **kanshi** и описать профили — тогда скрипт можно удалить совсем.

## Обои

Путь по умолчанию зашит в `config` (`~/Pictures/Wallpapers/frieren_meme.webp`) — замените
на свой. `Super + W` открывает выбор из `~/Pictures/Wallpapers`; выбранный путь сохраняется
в `~/.config/sway/wallpaper`, в git не попадает и подхватывается экраном блокировки.

## Внешний вид

`Super + ]` → `look.sh` — меню внешнего вида:

| Пункт | Что настраивает |
| --- | --- |
| `Theme` | цветовую тему: `ice` (светлая голубая) / `forest` (светлая изумрудная) / `dracula` (тёмная) |
| `Border` | толщину рамки окон в px — пресеты или произвольное число |
| `Smart borders` | `on` — прятать рамку у единственного окна (поведение по умолчанию) / `off` — рамки видны всегда |
| `Gaps` | отступы между окнами в px (видны и у единственного окна) |
| `Bar` | режим панели: `edge` (прижата к краю) / `floating` (ободок в цвет темы; отступы сверху и снизу равны `Gaps` — верх и низ вровень с окнами, — слева фиксированные 8 px) |

Всё применяется на лету и запоминается. Тема — это данные в git: папка
`sway/.config/sway/themes/<имя>/` с фрагментом на каждое приложение (`sway`,
`waybar.css`, `fuzzel.ini`, `mako`, `foot.ini`, `swaylock`) и маркером семейства
`family` (`light`/`dark` — от него зависят GTK и сигнал foot). Своя тема =
скопировать папку и поменять цвета. Текущий выбор лежит в state-файлах рядом с
конфигами (`~/.config/sway/{theme,border,smart-borders,gaps,bar-mode,look}`,
`~/.config/waybar/{theme.css,state.json,state.css}` и т.д.) и в git не попадает —
как `wallpaper`.

Как применяется:

| Компонент | Механизм |
| --- | --- |
| sway | цвета — через `swaymsg reload`; рамка, smart_borders и gaps — точечными `swaymsg` (так мгновенно и без лишнего рестарта waybar) |
| waybar | цвета — `theme.css` (импорт из `style.css`), margins — `state.json` (include из `config.jsonc`), ободок — `state.css`; перечитывается по `SIGUSR2`, в т.ч. при смене gaps (отступы floating-панели сверху и снизу равны им) |
| mako | `makoctl reload` |
| fuzzel, swaylock | ничего: конфиг читается при каждом запуске (swaylock — цвета флагами из `lock.sh`) |
| foot | SIGUSR1/2, мгновенно для всех окон: theme.ini собирается из палитр всех тем сразу, а стартовую задаёт `initial-color-theme` текущей |
| GTK | тёмность — вариантом встроенной `Adwaita` через `gtk-application-prefer-dark-theme` + `color-scheme`: пишется и в `~/.config/gtk-3.0`/`gtk-4.0/settings.ini`, и в gsettings (портал, libadwaita, браузеры). Имени `Adwaita-dark` не используем: отдельной темы с таким именем может не быть (она в `gnome-themes-extra`), и тогда GTK молча откатывается на светлую |

Цвета в базовых конфигах sway и mako оставлены нарочно: это фолбэк, совпадающий
с темой `ice`, — свежая система до первого `ensure` выглядит как раньше.
Недостающие state-файлы `look.sh ensure` создаёт сам (он есть и в автозапуске
sway, поэтому после первого входа в сессию всё уже на месте).

Две оговорки про чужие тулкиты:

- уже запущенные GTK-приложения тему подхватывают не всегда — перезапустите их;
- Qt-приложения (Happ и др.) системную тему на sway не видят вовсе: Qt не читает
  color-scheme портала без платформенной темы (QTBUG-141102). У Happ своя
  настройка: Настройки → Тема. Перекрасить все Qt разом можно через **qt6ct**,
  но это новая зависимость и переменная окружения — осознанно за рамками.

## Скрипты

`Super + ]` показывает плоский список `scripts/**/*.sh` через fuzzel. Скрипты из подпапок
требуют sudo и поэтому запускаются в терминале.

| Скрипт | Что делает |
| --- | --- |
| `lock.sh` | блокировка теми же обоями, что на рабочем столе |
| `look.sh` | меню внешнего вида: тема, рамки, gaps, режим панели |
| `wallpaper.sh` | выбор и применение обоев |
| `screenshot.sh` | скриншот области в файл и буфер |
| `powermenu.sh` | logout / suspend / reboot / shutdown |
| `brightness.sh up\|down` | яркость: brightnessctl для eDP-1, DDC/CI для внешнего |
| `monitors-fallback.sh` | eDP-1 вкл/выкл по наличию DP-1 |
| `power_management/power-profile.sh` | TDP + boost + EPP: eco / balanced / performance |
| `power_management/toggle_health_mode.sh` | лимит заряда 80% (Acer WMI) |

## Заметки

- В sway нет dwindle-тайлинга — спираль даёт демон `autotiling`.
- Скруглений, блюра и прозрачности в sway нет: активное окно видно по голубой рамке.
  Нужны эффекты — поставьте **SwayFX**, конфиг совместим.
- Заголовок окна в панели повёрнут штатным `"rotate": 90` (нужен waybar ≥ 0.10).
  На более старой версии верните `custom/window` со скриптом.
- Полоса-индикатор «куда откроется следующее окно» отключена: `indicator` равен
  цвету рамки (отдельной опции у sway нет). С gaps она выглядела чужой гранью.
- Палитра foot приезжает include'ом из `theme.ini`, которую `scripts/look.sh`
  собирает из палитры выбранной темы и темы противоположного семейства: у foot
  только два слота — `[colors-dark]` и `[colors-light]` — и нет перечитывания
  конфига, поэтому оба слота заполняются палитрами для корректного живого переключения.
- Иконки в лаунчере требуют явной `icon-theme` в `fuzzel.ini`. `icons-enabled` включён
  по умолчанию, но тема по умолчанию — `hicolor`, а он почти пустой, поэтому список
  выглядит вообще без иконок. Сейчас стоит `Adwaita`; любая другая тема — это просто
  имя папки в `/usr/share/icons` (например `Papirus` из `papirus-icon-theme`).
- `swaymsg reload` не перезапускает строки `exec` — только `exec_always`. После правок
  в автозапуске нужен перезаход в сессию, а не reload.
