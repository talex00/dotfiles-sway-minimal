# Миграция свёрнутых ссылок Stow

`migration.py` — отдельная консервативная миграция существующей установки,
не установщик для пустого HOME и не интеграция Theme Engine 2.0. Python 3,
GNU Stow и стандартная библиотека Python уже присутствуют в Ubuntu 24.04.
Существующая активная система при разработке не изменялась.

## Что делает

Инструмент принимает только известные свёрнутые ссылки пакетов в `.config`,
`.local/share/xfce4` и `.local/bin/sway-satellite.sh`. Папки становятся
обычными каталогами; совпадающие неизменяемые файлы ссылаются отдельно на
новый проект. Известные изменяемые файлы и отсутствующие в новом проекте
пользовательские файлы копируются обычными файлами. `monitors*` и
`workspace*` сохраняются как обычные файлы. Состояние XDG не перемещается и
не удаляется. При расхождении обычного файла между старым и новым проектами,
внутренней, чужой или битой ссылке и неоднозначном объекте выполнение
останавливается для ручной проверки. Исключение — конкретное обновление файла,
явно указанное через `--allow` в JSON с обоими SHA-256, типом, правами и
обоснованием. Неиспользуемая или устаревшая запись блокирует preflight.

По умолчанию выполняется read-only dry-run. Для применения необходим именно
его `PLAN-SHA256`; если данные изменились, план нужно построить заново.
Используйте разные `--id` для разных попыток. Backup по умолчанию находится в
`$HOME/.local/state/sway-minimal/migrations/<id>`; можно передать `--backup`,
но он должен быть внутри целевого HOME, вне `.config` и исходников, на той же
файловой системе, что и все заменяемые ссылки.

```sh
python3 experimental/test-migration.py
python3 experimental/migration.py --inventory --allow "$PWD/experimental/approved-updates.json"
python3 experimental/migration.py --dry-run --home /path/to/test-home --old /path/to/old --new /path/to/new --id test
python3 experimental/migration.py --apply --home /path/to/test-home --old /path/to/old --new /path/to/new --id test --expect PLAN_SHA256
python3 experimental/migration.py --verify --home /path/to/test-home --old /path/to/old --new /path/to/new --id test
python3 experimental/migration.py --restore --home /path/to/test-home --old /path/to/old --new /path/to/new --id test
```

Для проверенного сравнения реальных файлов используйте только read-only:

```sh
cd ~/dotfiles-sway-ubuntu-minimal-next-20261112
python3 experimental/migration.py --inventory --allow "$PWD/experimental/approved-updates.json"
python3 experimental/migration.py --dry-run --allow "$PWD/experimental/approved-updates.json"
```

Манифест разрешает точные пары хешей `look.sh`, `lock.sh` и `fuzzel-menu.sh`.
Это техническое согласование версий, **не разрешение на реальную
миграцию**. Никакого общего `--force` нет. Данные согласования, пути,
содержимое и типы файлов, режимы, идентификаторы и цели ссылок входят в
`PLAN-SHA256`; apply повторно читает всё перед переключением.

`--apply` повторно проверяет план, создаёт архив оригинальных ссылок и
содержимого старых каталогов и сверяет хеши файлов в архиве с планом до
изменения целевых ссылок. Подготовленные каталоги и операции описываются в
manifest; исходные ссылки перемещаются в backup, а не уничтожаются. Доступ к
HOME сериализован advisory `flock` на открытом `.config` между вызовами этого
инструмента. После успеха `--verify` сравнивает дерево с manifest и выполняет
  Stow **в режиме симуляции** с явным списком исключений изменяемых файлов.
Команда симуляции выводится на экран. Обычный Stow без этих исключений не
является проверенным способом обновления.

`--restore` сначала проверяет весь набор каталогов, архив и исходный старый
проект. Новые или изменённые файлы после миграции и изменения старого проекта
блокируют восстановление: их нельзя перезаписать автоматически. После
проверки прежние ссылки возвращаются, а мигрированные и частично подготовленные
деревья сохраняются в `saved-trees` в backup, а не удаляются. Восстановление
после SIGKILL при переключении ссылки проверено в тестовом HOME.

## Ограничения и граница безопасности

* Без `--allow` dry-run блокирует различающиеся скрипты. С согласованием
  конкретных хешей файлы можно включить в план; любые последующие изменения
  потребуют повторного анализа и нового плана. Подробнее в RECONCILIATION.md.
* Не запускайте `--apply` или `--restore` для реального HOME без отдельного
  разрешения. Нужны также свежая внешняя резервная копия и проверка плана.
* Механизм не предназначен для уже частично развёрнутых директорий: такие
  случаи требуют ручной инвентаризации. Неизвестные внутренние ссылки,
  специальные файлы и конфликтующие изменения блокируются.
* Защита от конкурентных вызовов относится только к этому инструменту;
  посторонние процессы не соблюдают advisory lock. Во время реальной миграции
  приложения, которые меняют конфигурацию, необходимо остановить отдельно.
  Между проверкой и отдельными системными вызовами остаются окна гонки;
  полная защита от параллельных изменений не гарантируется.
  Путь записи GTK 3/4 и файла темы Xcursor вне пакетов также проверяется на
  ссылки; автоматическое изменение этих настроек миграция не выполняет.
* Проверялось принудительное завершение процесса, а не отказ питания. Полная
  crash-durability при потере питания не обещается. При ошибке до появления
  manifest целевые ссылки ещё не менялись; backup может остаться неполным.
* Проверка Stow намеренно исключает изменяемые имена; она не является проверкой
  работы графической сессии или интеграции генератора v2.
